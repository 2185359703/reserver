# 无感验证 (silent) 本地还原说明

**目标**：还原 `request-无感` 这条 curl 请求（`POST /cap_union_new_verify`，`tlg=952`，
`ans=[{"elem_id":0,"type":"DynAnswerType_TIME","data":""}]`）。

**结论**：已 100% 还原并实测通过 —— 连续 3 次独立运行拿到真实 `tr03...` ticket。

## 一、项目思路回顾（Dan/Projeck）

该项目实现了腾讯行为式验证码的本地自动通过，核心能力：

| 参数 | 来源 | 实现 |
|---|---|---|
| `collect` | `tdc_collect.py` | 逆向 Chaos VM 混淆的 tdc.js → 提取 DELTA/偏移常量/密钥/明文模板 → 纯 Python XTEA 变体加密 |
| `tlg` | `len(collect)` | collect 字符串长度 |
| `eks` | 正则提取 | `window.XXX='...'` |
| `sess` | prehandle | `cap_union_prehandle` 接口返回 |
| `ans` | 业务 | 滑块=`DynAnswerType_POS` 坐标 / 无感=`DynAnswerType_TIME` 空数据 |
| `pow_answer` | MD5 暴力搜索 | 本地 hashlib |
| `pow_calc_time` | 本地计时 | PoW 耗时 ms |

## 二、无感验证与滑块验证的区别

同一套接口、同一套 7 参数，只有两处不同：

| 维度 | 滑块 (`request-滑块`) | 无感 (`request-无感`) |
|---|---|---|
| appid | `199999861` | `198550928`（官网无感 demo） |
| prehandle | `subcapclass=2401`，`fg_elem_list` 含滑块元素 | `subcapclass=1001`，`fg_elem_list=[]` 无交互元素 |
| `ans` | `[{"elem_id":1,"type":"DynAnswerType_POS","data":"x,y"}]` | `[{"elem_id":0,"type":"DynAnswerType_TIME","data":""}]` |
| 缺口检测 | 需要（OpenCV 融合 3 算法） | **不需要** |
| `tlg` | ~1688 | ~952（实际动态，本地实测 712~752） |

> `tlg` 是 `collect` 字符串长度，随 tdc.js 版本和明文内容动态变化，本地生成值不同属正常。

## 三、还原链路（replay_silent.py）

```
prehandle(appid=198550928)
  ├─ sess / pow_cfg / tdc_path
  ├─ PoW: md5(prefix+counter)==target → pow_answer, pow_calc_time
  ├─ 下载 tdc.js → tdc_collect.gen_collect() → collect + eks
  ├─ ans = [{"elem_id":0,"type":"DynAnswerType_TIME","data":""}]
  └─ POST cap_union_new_verify → errorCode=0 + ticket
```

## 四、运行

# 单次

# 连续 3 次，间隔 12 秒（注意风控）
python replay_silent.py --times 3 --gap 12

## 五、关键发现

1. **appid 决定验证模式**：`198550928`（官网无感 demo，来自
   `cloudcache.tencent-cloud.com/qcloud/tycaptcha/captcha.*.js` 中 `noFeel_click` 按钮）。
   用滑块 appid 提交 TIME 空数据会返回 `errorCode=50`。
2. **无感模式免交互**：`fg_elem_list=[]` 时无需缺口检测，直接 PoW + collect + 空 ans。
3. **tdc.js 版本会变**：新版本首次提取密钥偶发失败（`offsets insufficient`），
   脚本已加 3 次重试。
